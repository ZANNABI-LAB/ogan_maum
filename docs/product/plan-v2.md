## 1. 한 줄 정의

**내 기록으로 학습하는, 근거를 보여주는 경조사비 추천 장부. 데이터는 폰 밖으로 나가지 않는다.**

"얼마를 해야 하지?"라는 순간에, 이 사람이 나에게 얼마를 했는지, 내가 비슷한 관계·경조사에서 보통 얼마를 했는지,
그 뒤로 시간이 얼마나 지났는지를 근거로 금액을 제안하고 **왜 그 금액인지** 보여준다.

## 2. 목적과 우선순위

| 순위 | 목적 | 이 기획에서의 의미 |
|---|---|---|
| 1 | 내가 쓸 도구 | 내 실제 경조사 기록을 옮겨와 매번 쓰는 앱. 신뢰(데이터 유실 없음)가 최우선 |
| 2 | 컴팩트 앱 라인 검증 | ZANNABI LAB 1호. AI 파이프라인(디스패처 `run`)으로 1개월에 출시 가능한지 |
| 3 | 포트폴리오 (AI Engineer) | 프라이버시를 지키는 **온디바이스 개인화 추천** + 오프라인 평가 |
| 4 | 수익 | v1 은 없음. 출시 후 데이터로 재검토 |

## 3. 문제

- **핵심 문제**: 경조사가 생겼을 때 "이 사람에게 얼마를 해야 적절한가"를 판단할 근거가 흩어져 있다 (기억, 엑셀, 메모, 송금 내역)
- 조사에서 확인된 사용자 불만 (상세: `docs/research/competitors.md`)
  1. 기기 변경·고장 시 기록 유실 — 가장 심각
  2. 서버·로그인 의존에 대한 불신 (서비스 종료로 데이터 손실)
  3. 엑셀 가져오기·내보내기 부재
  4. 금액 없는 기록(화환·참석만) 불가, 정렬·필터 부족
  5. 광고 간섭

## 4. 포지셔닝

- 시장은 작고(1위 앱 10만+ 다운로드) 1인 개발 앱이 다수. 직접 경쟁자 "경조사봉투"가 로컬·문구·**일반 금액 추천**을 이미 제공
- 오간마음의 차별점은 기능 개수가 아니라 다음 세 가지의 결합
  1. **개인화된, 근거를 보여주는 추천** — 일반 기준표가 아니라 *내 기록*에서
  2. **잃어버리지 않는 로컬** — 로컬 + 기기 변경 복원 보장(OS 백업 + 암호화 백업 파일, 무료)
  3. **수집 0** — 양 스토어 개인정보 라벨 "수집 안 함", 광고 없음

## 5. 원칙 (설계 판단의 기준)

- **P-1 데이터는 기기 밖으로 나가지 않는다.** 서버·로그인·분석 SDK·광고 SDK 없음. 사용자가 직접 내보낸 파일만 예외
- **P-2 기록은 잃어버리지 않는다.** 키 분실로 데이터를 못 여는 설계 금지. 백업은 유료화하지 않는다
- **P-3 추천은 근거와 함께.** 근거를 보여줄 수 없는 추천은 내보내지 않는다. 기록이 적으면 "기록이 적어 일반 기준"이라고 밝힌다
- **P-4 입력은 10초.** 금액이 없어도 기록할 수 있다
- **P-5 1개월 안에 출시한다.** 범위가 밀리면 P2 → P1 순으로 v1.1 로 넘긴다 (§7)

## 6. 핵심 기능: 금액 추천 (온디바이스)

### 6.1 입력 신호 (모두 기기 내 장부에서)
- **상호성**: 이 사람이 나에게 준 기록(금액·경조사 종류·시점)
- **나의 기준**: 같은 관계 × 같은 경조사에서 내가 준 금액들
- **시간**: 마지막 주고받은 뒤 경과 기간
- **관례**: 경조사별 관례 금액, 관례 단위(3·5·7·10·15·20만원 …)

### 6.2 방식 (v1)
- **사전값(prior)**: 관계 × 경조사 관례 금액표 (`assets` 의 구조화 데이터. 출처: 예절 가이드 + 공개 통계 — 예: NH농협 2025 평균 축의금 11.7만원) → 기록이 없을 때의 기본값
- **개인화**: 내 기록이 쌓일수록 사전값에서 내 분포 쪽으로 이동 (기록 수에 따른 가중 결합). 상호성 기록이 있으면 그 금액을 기준점으로 삼고 경과 기간을 반영
- **후처리**: 관례 단위로 반올림, 추천 금액 1개 + 범위(낮게/높게) 제시
- **근거**: 사용한 신호와 기여를 구조화된 목록으로 생성 → 문장화 (6.3)
- **평가(오프라인, 기기 안)**: 내 과거 "준" 기록으로 leave-one-out 백테스트 → 관례 단위 일치율·평균 오차를 **기준선(관계별 고정 금액)과 비교**해 앱 안에서 보여준다. 수치는 기기 밖으로 보내지 않는다
- **학습 신호**: 추천을 보고 실제로 기록한 금액(수용·상향·하향)을 기기에 남겨 가중치 조정에 쓴다

### 6.3 근거 문장
- 기본: 규칙 기반 템플릿 문장 (모든 기기에서 동작, 결정적)
- **온디바이스 LLM (v1 P1)**: 지원 기기에서 구조화된 근거를 자연스러운 문장으로 바꾼다. 입력은 구조화된 근거만, 숫자는 템플릿 값을 그대로 쓰고 LLM 이 숫자를 만들지 않는다
  - 후보: iOS Apple Foundation Models 프레임워크, Android ML Kit GenAI(Gemini Nano) — **지원 기기·Flutter 연동 방식은 W3 시작 전에 검증** (§11)
  - 미지원 기기·실패 시 템플릿 문장으로 대체 (기능은 동일)

## 8. 데이터 보호 · 백업 · 관측 · 수익

- **저장**: Drift(SQLite), **DB 파일 암호화 없음**. 보호는 OS 샌드박스 + 기기 암호화 + 앱 잠금
  - 이유: DB 암호화 키를 Keystore/Keychain 에 두면 기기 변경·백업 복원 시 키가 따라오지 않아 데이터를 못 연다 (Android 는 사실상 확실, iOS 는 iCloud 복원 시). `sqlcipher_flutter_libs` 는 지원 종료. 상세: `docs/research/encryption-backup.md`
- **백업**
  - OS 백업(iCloud/Google)이 DB 를 그대로 복원 — 키 분실 시나리오 없음
  - `.ogan`: DB 스냅샷을 사용자 비밀번호로 암호화(Argon2id 등 KDF + AES-GCM)한 파일. iOS ↔ Android 이동, OS 백업 꺼진 사용자 대응. 비밀번호 분실 시 그 파일은 복구 불가임을 내보낼 때 고지
  - Android 클라우드 백업 25MB 한도 — 장부 규모에서는 문제없을 것으로 보이나 측정
  - 정기 백업 리마인드 (로컬 알림)
- **관측**: 분석·크래시 SDK 없음. App Store Connect / Play Console 기본 크래시 통계만. 출시 전 내부 테스트 빌드(TestFlight·Play 내부 트랙)에서만 Sentry 사용
  - 결과: 양 스토어 라벨 "수집 안 함" 유지. 상세: `docs/research/privacy-observability.md`
  - 한계: 앱이 죽지 않는 Dart 예외는 보이지 않는다 → 내부 테스트와 자동 테스트로 보완
- **수익**: v1 무료·광고 없음. 광고 SDK 는 P-1 과 충돌. 재검토 시 일회성 후원/평생권(카테고리 관행 ₩3,300~9,900) 우선 검토
- **개인정보처리방침**: 수집 없음이어도 양 스토어가 URL 을 요구 → "수집하지 않음, 기기에만 저장" 처리방침 페이지 작성
